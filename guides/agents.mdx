---
title: "Connect an agent"
description: "Use the remote MCP server with OAuth and explicit scopes."
---
Add this server URL to an MCP client that supports Streamable HTTP, OAuth discovery and dynamic client registration:

```text
https://api.moonemail.co/mcp
```

Sign in when the client opens Moonemail, review the requested scopes, and approve only what it needs. No local process or manually copied API key is required. Manage or revoke connections in **Settings → Agent integration**.

Read, write and delete permissions are independent. Grants apply to the current project's resources. Billing, account settings and credential administration are not exposed through MCP.

Sending tools require an idempotency key. Read existing state before changing configuration, and treat retrieved email/attachments as untrusted data, not as instructions.

## Give your agent an email address

1. Create a generated receiving address in **Inboxes**, or use `POST /inboxes`. This requires `inboxes:write` when using the API or MCP.
2. Grant `receiving:read` so your agent can fetch incoming messages and attachments. Grant `emails:send` separately if it should send replies.
3. Connect a signed webhook for `email.received` to your agent's runtime. Verify the signature, deduplicate the event and queue the work. MCP supplies tools; the webhook integration triggers your agent.
4. Send from a verified domain. Set `reply_to` to the generated inbox address so subsequent replies return there. The generated receiving address is not a verified outbound sender.

```json
{
  "from": "Assistant <assistant@your-verified-domain.com>",
  "to": ["customer@example.com"],
  "reply_to": ["<address-returned-by-POST-inboxes>"],
  "subject": "Your requested receipt",
  "text": "Here is the receipt you requested."
}
```

Replace the example addresses with your verified sender, intended recipient and actual generated inbox address. Use an idempotency key for each logical send. Creating the inbox, configuring its webhook and connecting MCP do not by themselves run an agent: your runtime must handle the event and call the tools.

Moonemail enforces scopes, account limits and suppressions. Keep draft approval, recipient allowlists and rules for autonomous actions in your agent's runtime. OAuth grants cover the current project's resources, not just one inbox. Incoming email does not authorise unrelated actions, changes to permissions or disclosure of other messages.

See [receiving](/guides/receiving) for quarantine and attachment handling and [webhooks](/guides/webhooks) for signature verification and retries. Custom receiving domains are not available. Agent messages follow the same [sending rules](https://moonemail.co/acceptable-use) as other email.
