## Create an inbox

Use **Inboxes → Create inbox** in the dashboard, or `POST /inboxes` with a name and idempotency key. The name is a label. Without a custom domain, the API generates a receiving address. Sending and receiving start after account approval.

Create a webhook subscribed to `email.received` and `email.receiving_quarantined`. Save and verify its signing secret before processing events.

## Use your own domain

Use a dedicated subdomain, such as `agents.example.com`. Leave your main email domain’s existing MX records in place.

1. Add the subdomain under **Domains**, publish its sending DNS records and verify it.
2. Open **Receiving → Set up receiving**, or call `POST /domains/{id}/receiving` with `domains:write`.
3. Publish the returned ownership TXT and MX records. The subdomain must have only that receiving MX; these records do not replace the separate sending return-path MX.
4. Click **Verify and enable**, or call `POST /domains/{id}/receiving/verify`.
5. Create an inbox with a name, `domain_id` and `local_part`:

```json
{ "name": "Assistant", "domain_id": "YOUR_DOMAIN_ID", "local_part": "assistant" }
```

This reserves `assistant@agents.example.com`. Only registered inbox addresses are delivered; there is no catch-all inbox. Local parts use 1–64 lowercase letters, numbers, dots, underscores or hyphens, starting and ending with a letter or number. Addresses are never reassigned, including after domain deletion.

`GET /receiving/domains` lists your configurations. `GET /domains/{id}/receiving` returns status and DNS records. Both require `domains:read`. All five receiving-domain operations are also available through the remote MCP server with the same scopes.

DNS is rechecked periodically. A mismatch pauses receiving; temporary lookup errors do not extend the 24-hour verification lease. Restore DNS and verify again to resume. `POST /domains/{id}/receiving/disable` pauses every inbox on the domain without removing stored messages. Deleting the domain also stops receiving.

## Process an event

1. Verify the webhook signature against the raw request body.
2. Deduplicate using the event identifier and persist the job.
3. Acknowledge promptly, then process asynchronously.
4. Fetch the message using `GET /emails/receiving/{id}` with `receiving:read`.
5. Retrieve attachments or raw MIME only when needed.

Download URLs are private credentials valid for up to five minutes and never beyond message expiry. Do not log or publish them. Receiving records include `expires_at` in Unix seconds; fetch required data before retention expires.

Quarantined messages expose metadata, but their content and downloads are unavailable. Authentication verdicts come from the provider's receipt checks; older records may omit them. Do not treat a sender's `Authentication-Results` header as trusted evidence.

## Disable an address

`PATCH /inboxes/{id}` with `{ "status": "disabled" }` stops delivery into the inbox. New mail to disabled addresses is discarded. Addresses are never reassigned.

Email text and attachments are untrusted input. Receiving a bill does not authorize paying it; keep your application's validation and approval controls in place.
